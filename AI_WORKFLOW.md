# AI Coding-Agent Workflow

## Tools
- **Chat assistant** (Grok Bot): requirement analysis, design discussion, planning, independent verification scripts (Python `Decimal`), spreadsheet cross-check.
- **Cursor Cloud Agent** (default model): implementation, tests, docs, UI iterations. Most of the application code was generated by the agent; I reviewed, directed, and verified every change and can explain and modify all of it.

## My workflow
1. **Analyze & clarify** – feed the spec to the AI, ask it to extract requirements, edge cases, and ambiguities.
2. **Grill me** – ask the AI to challenge my design with questions until the best approach is clear.
3. **Split into phases** – turn the decisions into small, verifiable phases.
4. **Implement** – delegate one phase at a time with explicit constraints and acceptance criteria.
5. **Verify** – check results against an *independent* source (not the agent's own output), then iterate.

---

## 1. Requirement analysis and clarification
- **Goal / context:** Understand a 5-page spec quickly and find where points are actually scored.
- **Prompt (excerpt):** "From this document, analyze and clarify the requirements. Summarize what must be built, the evaluation weights, the calculation rules, and the easy-to-get-wrong edge cases."
- **Agent response:** Summarized the scope; highlighted that AI workflow (35%) and calculation correctness (30%) dominate while UI is only 10%; listed pitfalls: reset to zero after a full close, SELL must not change average cost, BUY fee capitalized vs SELL fee reducing proceeds, rejecting SELLs that exceed holdings, float precision.
- **My review:** Re-read the Calculation Rules and Validation sections line by line against the list; confirmed nothing was missing (e.g. price `as_of` display, all-or-nothing import).
- **Outcome:** Accepted. Decided to spend effort on correctness and verification, not visual polish.

## 2. Grilling the design (architecture & data model)
- **Goal / context:** Choose the simplest architecture that is still correct and deployable.
- **Prompt (excerpt):** "Grill me with questions to find the best way to implement this: stack, numeric type, where state lives, how import stays atomic, what not to build."
- **Agent response:** Questions and proposals around: `number` vs a decimal library; DB or not; serverless state on Vercel; server- vs client-side calculation; API format for money.
- **My review / decisions:**
  - `decimal.js` everywhere; API returns **decimal strings** so precision is never lost in JSON; round only in the formatter.
  - No DB, no auth, no live prices (spec says not to over-engineer). Bundled CSVs are the default source; uploads are validated fully, then swapped in as a whole.
  - Pure, deterministic engine in `src/lib/portfolio.ts`, separate from parsing (`src/lib/import.ts`) and UI.
- **Outcome:** Accepted with these constraints; tradeoffs documented in README.

## 3. Phase plan
- **Goal / context:** Make the work reviewable in small steps.
- **Prompt (excerpt):** "Split this into phases with time estimates and what each phase must prove before moving on."
- **Agent response:** 5 phases – setup, design, engine + tests (most important), UI, deploy + docs – each mapped to spec sections.
- **My review:** Reordered so tests with known numbers come *before* UI, so UI work can't hide calculation bugs.
- **Outcome:** Accepted with that change.

## 4. Implementation – engine, import, UI
- **Goal / context:** Build the app per the phase plan.
- **Prompt (excerpt, to Cursor Cloud Agent):** "Build the assessment in the attached spec. decimal.js for all math, round only for display; Zod for CSV contracts; pure calculation module separate from import/validation and UI; all-or-nothing import with per-row actionable errors; tests asserting known numbers incl. a full-dataset reconciliation with these independently computed values: totals value 60620.89, cost basis 59969.24, realized -5052.96 … If your engine disagrees, investigate rather than force it."
- **Agent response:** Next.js + TS app, engine, import validation, API routes, KPIs, holdings, two charts, transaction explorer, tests, README.
- **My review:** Read the engine against the formulas; ran `npm test` / `npm run build` locally.
- **Outcome:** Accepted. Note the instruction "investigate rather than force it" – I did not want the agent to tune code until a test passes.

## 5. Verification against an independent source
- **Goal / context:** Prove the numbers are right without trusting the agent's own tests.
- **Prompt (excerpt):** "Compute the expected results directly from trades.csv/prices.csv with a separate Python script using Decimal(50 digits), following the spec formulas exactly."
- **Agent response:** Python script producing per-asset and total results; also a BTC spreadsheet with live Excel formulas per trade (running qty, cost basis, avg cost, cost removed, realized P&L).
- **My review:** Two independent implementations (Python and Excel formulas) matched the app to the cent, e.g. BTC cost basis 9,114.34, realized −463.75, unrealized −480.98, fees 486.42. Then asked for invariant tests: per-asset sums = totals, allocations sum to 1, total = realized + unrealized, SELL keeps avg cost, full close → 0, order-independence (shuffled input), cost basis never negative.
- **Outcome:** Accepted; `tests/reconciliation.test.ts` and `tests/invariants.test.ts` – 13 tests, all green.

## 6. Correcting / rejecting AI output (UI)
- **Goal / context:** Review the generated UI as a user would.
- **Issues found & actions:**
  - *Allocation chart reused colors* for different assets → asked for a stable, color-blind-friendly palette per asset, shared across both charts, with a legend.
  - *Import section layout broke* after an iteration → rejected the inline approach entirely and redirected: move the whole import flow into an accessible modal opened from the header.
  - The agent got stuck taking screenshots for verification → stopped that and told it to finish and run lint/test/build instead.
  - Header badge "Sample data" was unclear → changed to "Data: Sample / Data: <filename>" with status dot; added an Info modal showing the calculation rules.
- **Outcome:** Edited/redirected; each fix verified locally after pulling.

## 7. Debugging docs and repo hygiene
- **Goal / context:** Make the submission render correctly and be safe to publish.
- **Issues found & actions:**

  - The agent had committed an `uploads/` folder containing the original assessment PDF. Removed it, added to `.gitignore`, and rewrote history (`git filter-repo`) before keeping the repo public.
- **Outcome:** Fixed; README renders, no assessment materials in history.
